1 איך זה עובד — אדריכלות

ה-CP4-R מריץ Crestron Home OS. בשונה מ-CP4 רגיל, אי אפשר לטעון עליו תוכנית SIMPL מותאמת — ההרחבה היחידה הנתמכת היא Crestron Certified Driver (קובץ .pkg). מתחברים ל-Paradox דרך מודול APR-PRT3, שמדבר בפרוטוקול ASCII פתוח ומתועד (ה-IP150 לבדו סגור/מוצפן).

Paradox Panel ──RS-232──► APR-PRT3 ──RS-232──► [Serial↔Ethernet] ──TCP──► CP4-R (גלאים, מחיצות) (ASCII / Home Auto) (Lantronix/Moxa/USR) │ הדרייבר .pkg │ ┌──────────────────┬────────────────────────┘ ▼ ▼ Security Partitions Security Zones / Sensors דרוך / מנוטרל / אזעקה פתוח / סגור / תנועה │ │ └──────────────────┴──► מנוע האוטומציה של Crestron Home תנועה → אור → טיימר כיבוי

הדרייבר קורא מ-PRT3 בשיטת polling יציבה (שאילתות RZ/RA), מזהה שינויים, וחושף כל גלאי כ-Zone וכל מחיצה כ-Partition. את הלוגיקה "תנועה ← אור ← טיימר" בונים במנוע האוטומציה של Crestron Home — כך היא שקופה וניתנת לעריכה ע"י הלקוח בלי לקמפל מחדש.

חיבור RS-232 בין PRT3 לממיר (Null-modem הפוך)

APR-PRT3 Serial↔Ethernet ───────── ─────────────── TX ───────────────────► RX RX ◄─────────────────── TX GND ──────────────────── GND
⚠ שים לב TX של צד אחד מתחבר ל-RX של הצד השני (חיבור מוצלב). אם אתה רואה echo אך לא מקבל תשובות — סימן מובהק ש-TX/RX הפוכים.

הגדרות הפורט (זהות בשני הצדדים)

57600 bps · 8 data bits · No parity · 1 stop bit (8N1) · ללא בקרת זרימה.

הגדרת הממיר

  • כתובת IP סטטית (למשל 192.168.1.50)
  • פורט טורי: 57600 8N1, ללא flow control
  • מצב TCP Server (Raw / Transparent) על פורט (ברירת מחדל נפוצה 10001)
  • כיבוי Telnet / COM-Port-Control — רוצים זרם בייטים שקוף
ℹ רשום את ה-IP והפורט — תזדקק להם בהגדרת הדרייבר ובכלי האבחון.

5 בניית הדרייבר (קובץ .pkg)

דרישות מקדימות

  • חשבון מפתחים ב-Crestron (Developer account)
  • Crestron Drivers SDK — כולל ה-DLLים ו-ManifestUtil.exe
  • Visual Studio 2019+ (netstandard2.0)
  1. אמת את הליבה — הרץ את בדיקות ה-Python (python3 -m unittest test_paradox_prt3). מחלקת ParadoxProtocol ב-C# ממומשת לפי אותה התנהגות.
  2. חבר References ל-SDK — ב-.csproj עדכן את ה-HintPath ל-DLLים Crestron.RAD.Common ו-Crestron.RAD.DeviceTypes.Security.
  3. התאם את הקישור ל-SDK — ב-ParadoxPrt3SecurityDriver.cs אמת את חתימות מחלקת הבסיס מול גרסת ה-SDK שלך, ומפה את האירועים (ZoneChanged/AreaChanged) ל-API.
  4. קמפל ב-Release — הפלט הוא Mila_SecuritySystem_Paradox_PRT3_IP.dll.
  5. הרץ ManifestUtil — העתק את ה-DLL לתיקיית הכלי והרץ אותו. ייווצר קובץ .pkg.
ℹ מוסכמת שם <Developer>_<DeviceType>_<Manufacturer>_<BaseModel>_<Communication> → Mila_SecuritySystem_Paradox_PRT3_IP

6 העלאה ל-Crestron — צריך או לא?

תשובה קצרה לא צריך להעלות לאתר מפתחי Crestron כדי להשתמש בדרייבר במערכת שלך. אתה בונה את ה-.pkg בעצמך וטוען אותו ישירות ל-Crestron Home דרך ה-Setup App.
מסלולמתימה עושים
שימוש עצמי / לקוח שלך
זה מה שאתה צריך		 התקנה במערכת ספציפית מקמפלים .pkg מקומית (SDK + ManifestUtil) ← טוענים ישירות ב-Crestron Home Setup. בלי העלאה ל-Crestron.
הסמכה והפצה ציבורית
אופציונלי		 רוצים שהדרייבר יופיע במאגר הגלובלי לכל המתקינים מגישים ל-Crestron ב-"Submit a Driver" → תהליך אישור וחתימה רשמי

כלומר הזרימה שלך: בונה .pkg ← טוען ב-Crestron Home Setup ← גמרת. ההעלאה לפורטל המפתחים נדרשת רק אם תרצה להפיץ את הדרייבר מסחרית לאחרים.

7 הוספה ב-Crestron Home Setup

  1. טען את הדרייבר — ב-Setup App: Settings → Drivers → Load/Add Custom Driver → העלה את Mila_SecuritySystem_Paradox_PRT3_IP.pkg.
  2. הוסף התקן — Devices → Add Device → קטגוריה Security → בחר את הדרייבר.
  3. הזן הגדרות חיבור:
    שדהערך
    HostIP של הממיר (192.168.1.50)
    Port10001
    UserPinקוד משתמש לדריכה/נטרול (אופציונלי)
    Zonesגלאים לסקירה, CSV — 1,2,5,8
    Partitionsמחיצות — 1
  4. אמת תקשורת — הדרייבר צריך להראות Online. הזז יד מול גלאי → ה-Zone משתנה ל-Open וחוזר ל-Closed.
  5. מפה לחדרים — שייך כל Zone לחדר, תן שם ברור (סלון-תנועה, מחסן…), וסמן גלאי תנועה כ-Motion/Occupancy.

8 תנועה ← אור ← טיימר

זה לב הפרויקט. יש שתי דרכים — מומלץ מסלול א' (נייטיב Crestron Home).

מסלול א' (מומלץ) — Auto-Off של חדר

  1. ב-Rooms → (החדר) → Room Settings / Lights הפעל Occupancy-based / Auto-Off.
  2. בחר את גלאי התנועה של Paradox כמקור הנוכחות של החדר.
  3. הגדר Auto-Off Timeout = זמן הכיבוי (למשל 90 שניות / 2 דקות).
  4. בחר אילו עומסי תאורה נדלקים בנוכחות.
ℹ למה Auto-Off ולא Delay קשיח? גלאי PIR מדווח Open לרגע וחוזר ל-Closed. מנגנון ה-Auto-Off של החדר נועד בדיוק לזה — כל "תנועה" מאריכה את חלון הנוכחות ומאפסת את הטיימר. זו ההתנהגות שאתה רוצה.

מסלול א'2 — Automation/Events (גמיש)

אם רוצים תנאים: Trigger = גלאי עובר ל-Open + תנאי "המחיצה דרוכה"; Action = הדלקת סצנת תאורה; הכיבוי דרך Auto-Off של החדר או Delayed-Off אם הגרסה תומכת.

מסלול ב' — לוגיקה עצמאית (כלי הגישור)

ממומש ובדוק ב-Python (MotionLightController): תנועה ← light_on() ← טיימר; כל תנועה מאפסת; תום הטיימר ← light_off(); תנאי only_when_armed_area אופציונלי. מתאים להרצה על Raspberry Pi צמוד ל-PRT3.

# הרצת לוגיקת תנועה→אור→טיימר מתוך config.json
cd gateway
cp config.example.json config.json   # ערוך: גלאים, זמנים, פקודות הדלקה/כיבוי
python3 cli.py run --config config.json

9 אבחון ובדיקות

לפני שנוגעים ב-Crestron — אמת חיווט והגדרות PRT3 עם כלי ה-Python מכל מחשב באותה רשת:

cd gateway
python3 cli.py monitor --tcp 192.168.1.50:10001 --zones 1-8 --areas 1

# פלט לדוגמה בזמן תנועה:
# [ZONE 005] ZoneState.CLOSED -> OPEN
# [AREA 001] arm=armed alarm=ok

בדיקת לוגיקת הפענוח בלבד (ללא חומרה):

cd gateway && python3 -m unittest test_paradox_prt3 -v   # 22 passed
✓ עיקרון אם כלי ה-Python מצליח לקרוא מצבים אך Crestron לא — הבעיה ברשת/הגדרות הדרייבר, לא ב-PRT3.
