# 07 — אוטומציה: תנועה → הדלקת אור → טיימר כיבוי

זה הלב של הפרויקט: כשגלאי תנועה (באזור דרוך) מזהה תנועה — מדליקים אור,
מתחילים ספירת זמן, וכשהזמן נגמר (ללא תנועה נוספת) — מכבים.

יש שתי דרכים לממש. **מומלץ מסלול א'** (נייטיב Crestron Home).

---

## מסלול א' (מומלץ) — מנוע האוטומציה של Crestron Home

יתרון: הזמן והתרחיש ניתנים לעריכה ע"י הלקוח, ללא קמפול, ובניצול מנגנוני
התאורה המובנים.

### אפשרות א'1 — דרך תאורת חדר עם Auto-Off (הכי אלגנטי)
אם הגלאי נחשף כ-**Occupancy/Motion Sensor** ושויך לחדר:
1. **Rooms → (החדר) → Lights / Room Settings**.
2. הפעל **Occupancy-based lighting / Auto-Off**.
3. בחר את גלאי התנועה של Paradox כמקור הנוכחות של החדר.
4. הגדר **Auto-Off Timeout** = זמן הכיבוי הרצוי (למשל 2 דקות).
5. בחר אילו עומסי תאורה נדלקים בנוכחות.

מעתה: תנועה → אור נדלק; כל תנועה מאפסת את הטיימר; אין תנועה X דקות → כיבוי.
**הטיימר והאיפוס מטופלים ע"י Crestron Home מובנית.**

### אפשרות א'2 — דרך Automation/Events (גמיש יותר)
אם תרצה שליטה מדויקת או תנאים (רק כשדרוך, רק בלילה וכו'):
1. **Automation → Create Event** (או "Quick Action"/"Scheduler", לפי הגרסה).
2. **Trigger:** מצב גלאי האבטחה עובר ל-**Open** (תנועה).
   - הוסף תנאי: **המחיצה דרוכה** (אם רוצים שיפעל רק כשהבית דרוך).
3. **Action:** הדלק את עומס/סצנת התאורה.
4. כיבוי — אחת מהשתיים:
   - השאר את ה-**Auto-Off של החדר** (א'1) שיכבה, **או**
   - הוסף Action עם **Delay/Timer** (אם הגרסה תומכת ב-"Delayed Off")
     שמכבה אחרי הזמן הרצוי; אירוע תנועה חדש "מאפס" ע"י הדלקה מחדש.

> **למה Auto-Off ולא Delay קשיח?** גלאי PIR מדווח Open לרגע וחוזר ל-Closed.
> מנגנון ה-Occupancy/Auto-Off של החדר נועד בדיוק לזה — כל "Open" מאריך את
> חלון הנוכחות. זו ההתנהגות שאתה רוצה.

### דוגמת תרחיש (מחסן)
- גלאי "מחסן-תנועה" (Zone 5), מחיצה 1.
- כניסה למחסן → אור נדלק.
- כל עוד יש תנועה → נשאר דולק (טיימר מתאפס).
- 90 שניות ללא תנועה → כיבוי.

הגדרה: שייך Zone 5 לחדר "מחסן", הפעל Auto-Off=90 שניות, מקור נוכחות=Zone 5.

## מסלול ב' — לוגיקה עצמאית (בדרייבר או בכלי הגישור)

מתאים אם אינך רוצה להישען על מנוע האוטומציה של Crestron, או כשמריצים גישור
על Raspberry Pi צמוד ל-PRT3 (בלי לערב את Crestron בהחלטה).

הלוגיקה כבר ממומשת ב-Python (`gateway/paradox_prt3.py` → `MotionLightController`)
ובדוקה (ראו `test_paradox_prt3.py`):

- מעבר גלאי ל-Open (תנועה) → `light_on()` ואיפוס/התחלת טיימר.
- כל תנועה נוספת → **מאפסת** את הטיימר (לא מדליק שוב).
- תום הטיימר → `light_off()`.
- תנאי אופציונלי `only_when_armed_area` → פועל רק כשהמחיצה דרוכה.

### הרצה
```bash
cd gateway
cp config.example.json config.json   # ערוך: גלאים, זמנים, ופקודות הדלקה/כיבוי
python3 cli.py run --config config.json
```

`config.json` מגדיר לכל כלל: `zone`, `timeout_sec`, `only_when_armed_area`,
ופקודות `light_on_cmd`/`light_off_cmd` (למשל `curl` ל-API של ממסר/תאורה).

### דוגמת כלל (מתוך config.example.json)
```json
{
  "zone": 5,
  "timeout_sec": 90,
  "only_when_armed_area": 1,
  "light_on_cmd": "curl -s -X POST http://192.168.1.60/relay/0?turn=on",
  "light_off_cmd": "curl -s -X POST http://192.168.1.60/relay/0?turn=off"
}
```

> אם משלבים את לוגיקת הטיימר **בתוך הדרייבר** (במקום ב-Crestron Home), אפשר
> לעטוף את `MotionLightController` המקביל ב-C# — אך אז הדרייבר צריך גם לשלוט
> בעומס התאורה, מה שמסבך. לכן בתוך Crestron Home **מסלול א' עדיף**.
